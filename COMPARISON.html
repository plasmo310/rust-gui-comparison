  1. 配布先: ブラウザ → Leptos / デスクトップ+モバイル → Tauri, Dioxus / 組込み → Slint / Linux ネイティブ → GTK4
  2. チームのスキル: Web 経験者 → Tauri, Dioxus, Leptos / 純 Rust → egui, Iced

  4. 安定性: 0.x は API 追従コストを見込む。長期保守なら Tauri 2 / Slint 1 が有利
  5. IME・アクセシビリティ: 独自描画系 (egui, Iced, Slint) は日本語入力を実機で要確認

任意の CLI: cargo tauri（今回の構成では不要）、dx（公式によるとソースビルドは最大 10 分。ビルド済みバイナリ推奨）、Node.js（Tauri で JS フレームワークを使う場合のみ）。
実際に詰まった点:
  • Tauri: icons/icon.png が無いとビルドできない。設定と権限ファイルが必要。
  • eframe 0.36: App::update は廃止され App::ui(ui, frame) に変更。古い記事のコードはそのままでは動かない。
  • Leptos は cargo run では動かず trunk が前提。
  • GTK4: macOS は 1 コマンドだが、Windows の公式手順は最短でも GTK のビルドと環境変数設定が必要で最も重い。
総合（軽い順）: egui ≒ Iced ≒ Slint（ほぼ cargo run だけ）→ Dioxus ≒ Tauri（Linux でパッケージ導入）→ Leptos（trunk と WASM ターゲット）→ GTK4（特に Windows）
